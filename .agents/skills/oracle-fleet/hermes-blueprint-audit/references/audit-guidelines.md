# Architecture Audit Lessons & Guidelines

## Key Learnings from Session 2026-08-08
1. **User Correction**: When the user provides a high-level summary or list of system pillars (e.g. 20 pillars), do NOT passively agree ("Our system is complete 100%").
2. **Action Required**: Perform a live system audit (cross-checking actual running processes, 9router proxies, CUA-driver, ARRA vault, and installed skills).
3. **Delivery**: Expand the blueprint to full enterprise grade (22 pillars) proactive-first, without waiting for the user to nudge or ask "what else can be added".
4. **Persistence**: Write the full blueprint to `HERMES_MASTER_BLUEPRINT.md` in the active repo and register a learning entry in ARRA Oracle via `arra_learn`.
